# 문서 스킬 연동

| 항목 | 값 |
|---|---|
| 상태 | 제안 |
| 관련 결정 | [그림 문법과 배치를 직접 맡고 D2 호환을 버린다](../decisions/2026-10-01-own-syntax-and-layout.md) |

## 요약

문서 스킬 연동은 repo-docs-figures 스킬의 그림 도구 표에서 D2와 Vega-Lite 두 행을 이 도구 한 행으로 바꾸는 계약이다. 스킬의 그림 종류, 차트 종류, 색표, 글꼴, 변환 명령, 검사가 이 도구의 무엇에 대응하는지 정한다. 터미널 데모(VHS)는 그대로 둔다. 이 문서는 현재 계약과 확인한 증거만 적는다. 진행 기록, 검수 영수증, 이전에 남긴 검증 근거는 GitHub 이슈 요약에 둔다.

## 동기

지금 문서 스킬은 구조 그림을 D2로, 실험 차트를 Vega-Lite로 그리고, 두 도구에 같은 색을 넣으려고 변환 스크립트가 각 도구의 설정 형식으로 색표를 따로 넣는다. 글꼴은 보는 쪽에 설치되어 있어야 하고, D2 SVG에는 한글 글꼴이 들어가지 않는다. 도구가 하나면 색표, 글꼴, 여백, 움직임이 한 곳에서 정해지고, 스킬 규칙도 짧아진다.

## 예시

### 구성 요소 그림 변환

1. 기여자가 `docs/assets/architecture.dap`를 고친다.
2. 기여자가 저장소 루트에서 `python3 <스킬 폴더>/scripts/render_figures.py docs/assets/architecture.dap`를 실행한다.
3. 스크립트가 `daphnis render --strict docs/assets/architecture.dap`를 부르고, 같은 폴더에 움직이는 SVG `architecture.svg`가 생긴다.
4. 그림 검사 오류가 있으면 스크립트가 실패하고 결과 파일은 생기지 않는다.

### 실험 차트 변환

1. `03-analyze`가 `results/summary.json`을 쓴다.
2. `results/figures/accuracy.dap`의 `data "../summary.json" at "/accuracy"`가 그 값을 읽는다.
3. 원본에 숫자를 손으로 적지 않는다.

## 상세 설계

### 그림 종류 대응

| 스킬 그림 | 지금 | 이 도구 |
|---|---|---|
| 맥락 그림 | D2 `direction: right`, 그룹 `system` | `flow right`, `person`, `box system`, `external`, `store` |
| 구성 요소 그림 | D2 그룹 `system` 안 구성 요소 | `flow right`, `group system`, 안에 `box`, `store` |
| 순서 그림 | D2 `shape: sequence_diagram` | `sequence` |
| 상태 그림 | D2 `direction: down` | `state down`, `start`, `final` |
| 데이터 그림 | D2 `shape: sql_table` | `data right`, `table`, `fk=` |

| 스킬 도형 규칙 | 이 도구 |
|---|---|
| 사용자: `shape: person` | `person` |
| 이 시스템: 이름이 `system`인 그룹 | 맥락 그림은 `box system`, 구성 요소 그림은 `group system` |
| 구성 요소, 모듈: 기본 사각형 | `box` |
| 외부 프로그램, 외부 서비스: `style.stroke-dash: 4` | `external` |
| 파일, 데이터베이스: `shape: cylinder` | `store` |
| 테이블: `shape: sql_table` | `table` |

- 스킬의 "한 쌍에 선 하나, 방향은 요청이 가는 쪽" 규칙은 [그림 문법](figure-syntax.md)이 오류로 지킨다. 스킬 문장에서 뺀다.
- 스킬의 식별자 규칙(영어 소문자 kebab-case)은 그림 문법의 이름 규칙과 같다. 테이블 이름은 `_`를 쓰고, 열 이름은 대문자도 쓴다([그림 종류](figure-kinds.md)).
- 스킬의 순서 그림 규칙(참여자는 처음 메시지를 보내는 순서)은 도구가 경고로 알린다([그림 종류](figure-kinds.md)).
- Markdown 표는 이 도구의 대상이 아니다. 글로 된 표는 계속 Markdown 표로 쓴다.

### 차트 종류 대응

이 표는 스킬이 쓰는 Vega-Lite 차트가 도구의 무엇에 대응하는지만 정한다. 이 도구가 그리는 차트 종류 전체는 [차트](charts.md)가 정한다.

| 스킬 Vega-Lite 차트 | 이 도구 |
|---|---|
| `bar`와 `errorbar`, 기준선 `rule` | `chart bar`, `계열.low`, `계열.high`, `rule` |
| 덤벨 | `chart dumbbell` |
| 상자 그림 | `chart box` |
| 산점도 | `chart scatter` |
| 히트맵 | `chart heatmap` |
| 선 | `chart line` |

- 스킬의 "값은 `03-analyze`가 넣고 손 기재 금지" 규칙은 `data` 줄로 지킨다.
- 스킬의 "막대 축 0에서 시작, y축 둘 금지" 규칙은 [차트](charts.md)가 지킨다. 스킬의 "계열 둘까지"는 스킬 쪽 제약이고 이 도구의 계열 수 계약이 아니다. 색 수를 넘는 계열은 아래 색 계약의 무늬·모양·직접 라벨로 구분한다.

### 디자인 기준과 수용 게이트

시각 기준은 Things 공식 사이트 [culturedcode.com/things](https://culturedcode.com/things/), [기능 페이지](https://culturedcode.com/things/features/), 공식 네이티브 앱 화면 이미지다. 제목은 제목, 재생 조작은 조작, 카드는 카드처럼 역할이 같은 요소끼리 비교한다. 앱 화면 이미지도 역할 기준으로 유효하며 클래식 macOS 앱을 통째로 기준에서 빼지 않는다. 다만 지금 쓰는 앱 이미지는 2017년 사이트 영상 화면과 라이트·다크가 함께 있는 2018년 Things 3.7 화면이라 보조 참고이고, 현재 네이티브 버전과 같다는 근거가 아니다. UML 기호, 차트, 구성도처럼 직접 대응이 없는 요소는 같은 글자·면·선 규칙을 적용한 Daphnis 확장이지 Things의 구성 요소가 아니다. 예전에 쓰던 Refero 화면은 정규화한 측정값과 재구성 예제라 보조 참고일 뿐 기준이 아니다. Things의 로고와 제품 화면은 포함하지 않으며 별도 소개·문서 사이트도 만들지 않는다.

수용 게이트는 `npm test`와 별개의 화면 비교다. 모바일 320·390·430px와 데스크톱 실제 크기에서 공식 기준 화면과 나란히 비교하고, 라이트·다크와 정지·재생 중 상태를 확인한다. 필요한 브라우저가 없으면 게이트는 실패다. 건너뛴 검사를 통과로 세지 않는다. 자동 검사는 기능 증거이고 디자인 합격 증거가 아니며, 겹침·잘림 검사도 눈 검수를 대신하지 않는다. 정적 SVG 미리보기의 축소 이미지는 모바일 가독성 통과로 세지 않는다. 읽기용 화면은 재생기의 최소 글자 크기와 캔버스 내부 스크롤을 쓴다.

### 계약

| 요소 | 계약 |
|---|---|
| 핵심 색 | 파랑·노랑·빨강·초록 넷. 값은 공식 사이트 solid 2024 기능 아이콘의 면색이고 순서와 함께 바꾸지 않는다(원색 값은 바뀌지 않는 기록이다). 2017년 사이트 영상 스틸과 2018년 앱 화면 이미지는 역할 위계를 보는 보조 참고이고 그 색을 현재 네이티브 색으로 읽지 않는다. 대비를 맞추려고 핵심 RGB를 바꾸지 않는다. 사이트 기능 아이콘 색은 네이티브 앱 모든 역할의 같은 색이라는 근거가 아니다. 역할(면, 경계, 글자, 효과)마다 쓰는 값은 원색에서 계산한 파생이며 원색과 따로 기록한다. 관측한 페이지와 화면 위치는 이슈에 남긴다 |
| 확장 색 | 핵심 넷 밖의 색은 실제 팔레트 출처와 라이트·다크 실제 크기 구성 요소 검수를 거친 후보만 더한다. 지금 기록된 확장은 주황·보라·청록 셋이라 팔레트 개정 1의 계열은 일곱이다. 일곱은 개정 1의 기록일 뿐 고정된 최대가 아니다. 고른 순서는 한 번 기록하고 뒤에만 더하며 빌드마다 순열을 다시 찾지 않는다. 출처 없이 HEX를 고르지 않으며 이 문서에도 값을 복사하지 않는다 |
| 색 이동 | 고른 값 밖으로 색상·밝기를 자동으로 옮기지 않는다. 경계·글자색처럼 파생이 필요한 값은 후보 검수에서 고른 값으로 기록한다. 회색 윤곽을 섞지 않는다 |
| 같은 계열 경계와 효과 | 칠한 대상(노랑 막대, 노랑 카드)의 경계와 갱신 효과는 그 대상 계열의 색에서만 고른다. 다른 계열, 회색, 흰색, 갈색으로 바꾸지 않는다. 노랑은 같은 계열의 노랑 경계를 유지한다. 효과 색은 계열마다 테두리를 같은 색상에서 밝힌 한 단계(`color.data.category-effect.N`, `color.paint.<이름>.effect`, `categoryPaint().effect`)이고 원색은 바뀌지 않는다. 차트 표식의 겹침과 색을 직접 고른 도형(`fill=`, `stroke=`)의 도착 후광이 이 단계를 쓰며, 색을 고르지 않은 도형과 `gray`는 상태 파랑이다. 효과 색은 일시적인 보조 신호라 대비 3으로 맞추지 않는다(같은 변화를 값 글자, 라벨, 입력 표도 알린다). 효과 후광이 라이트·다크에서 얼마나 잘 보이는지는 사람이 따로 평가하지 않았다(검증 요구사항, 미완료) |
| 의미 아이콘 글리프 | 도형 안 의미 아이콘의 글리프 색(`color.figure.icon-{역할}-ink`)은 본문 글자색과 따로 둔 보조 역할이다. 다크에서는 같은 계열의 테두리 단계(`dark-border`)를 쓴다. 서비스와 사용자는 파랑, 데이터는 초록, 접근 제어는 노랑 계열이고 카드 면과 자기 세부 면 위에서 대비 3 이상이다. 원색(앵커)과 다크 카드 면은 바뀌지 않는다. 값은 토큰 소유 저장소가 정하며 이 문서에 복사하지 않는다. 다크 카드 위의 모습은 폭 390 다크 첫 장면 모음과 순서 예제 다크의 마지막 장면 실제 크기에서 보았다([표현 범위](expression-coverage.md#예제와-검증-범위)). 모든 아이콘 도형과 크기를 본 것은 아니다 |
| 색 수 초과 | 색 수에 고정 상한이나 오류 상한을 두지 않는다. 색을 넘는 계열은 무늬·모양 단계와 직접 라벨로 구분하며 색만으로 구분하는 조용한 되감기를 두지 않는다 |
| 대비 계산 | 면 위 글자 색은 검은색과 흰색 중 계산한 대비가 큰 쪽이다. 글자는 4.5 이상이다. 그래픽은 그 요소가 실제 그려지는 면과 역할(선, 면, 효과)마다 그 면 위에서 잰다. 모든 그래픽에 일률로 3을 요구하지 않고, 3에 못 미치는 노랑을 맞추려고 색을 바꾸지 않는다. 라벨, 번호 키, 무늬, 모양이 구분을 보완한다 |
| 화살촉 | 일반 연결선은 채운 삼각형이다. UML 관계(상속·구현·집합·합성·의존)는 모양이 곧 뜻이라 의미 있는 예외로 둔다 |
| 카드와 아이콘 | 카드 표면과 의미 아이콘은 한 구현을 공유한다. 그림 종류마다 복제하지 않는다 |
| 번호 배지 | 라이트는 어두운 면에 흰 숫자, 다크는 밝은 면에 어두운 숫자(`color.figure.number-fill`, `number-ink`). 범주 색을 쓰지 않는다. 글자 대비 4.5 이상 |
| 흐림 | 흐린 행은 면의 투명도만 낮추고 복제 테두리 같은 두 번째 경계층을 두지 않는다 |
| 사건 강조 | 지금 단계의 도형·선·이동 라벨은 한 공통 규칙으로 강조한다. 종류별 별도 강조를 두지 않는다 |
| hover | 의미 없는 장식 hover를 두지 않는다. 키보드 초점과 눌림 상태는 접근성 때문에 유지한다 |
| 결함 수정 | 덮어쓰기 CSS와 예제별 보정을 쓰지 않고 공통 규칙을 고친다 |

### 증거 표

자동 증거는 저장소에 있는 검사의 이름이고, 화면 비교는 위 수용 게이트를 실제로 수행한 기록이다. 화면으로 확인한 범위(예제 30개, 폭, 라이트·다크, 직접 본 화면, 공식 Things 역할 비교)는 [표현 범위](expression-coverage.md#예제와-검증-범위)의 표가 정하고, 그 범위를 넘는 칸은 검증 요구사항, 미완료다. 이전에 남긴 검증 근거와 개수, 날짜는 GitHub 이슈 요약에 있다.

|---|---|---|
| 글자 대비 | `contrast.test.js` | 없음 |

| 좁은 화면의 차트 가독성 | 없음 | 그래프와 차트 판은 컨테이너 폭(272)의 좁은 배치로 다시 그려진다. 눈으로 본 범위는 폭 390의 라이트·다크 첫 장면과 면적·산점도·원·상자의 실제 크기, 일반 Chrome 390의 산점도 조작까지이고, 320과 430의 눈 검수와 모든 종류·장면의 읽힘은 확인하지 않았다. 선 굵기는 모든 계열이 같은 토큰이다 |
| 데스크톱 실제 크기 비교 | 없음 | 폭 1440 라이트의 예제 30개 첫 장면 모음, 흐름 예제의 라이트 실제 크기, 순서 예제의 다크 마지막 장면, 혼합 화면(그래프, 차트, API, 스키마, 순서, 추적)을 직접 봤다. 모든 예제의 모든 장면과 폭 1440 다크는 아니다 |
| 선택 면 | 없음 | 현재 구현은 선택 면을 중립 회색으로 둔다. 공식 기준과 일치한다는 근거가 아니다 |
| 확장 색 후보 | 없음 | 보라와 청록은 실제 크기 라이트·다크 목업 비교로 골랐다. 제품 렌더러는 차트 여섯 종류를 라이트·다크의 색각 이상 에뮬레이션(적록, 무색각)으로 본 범위까지만 확인했다. 일곱 계열 산점도는 라이트·다크의 무색각 화면에서 점과 번호 키가 모두 그려지는 것을 직접 확인했다. 색각 이상 실제 사용자 시험은 검증 요구사항, 미완료다 |

### 색 역할

공통 색과 그림 전용 색의 정본은 [design-tokens](https://github.com/woonyong-choi/design-tokens)의 simple2다. 기본 단계와 역할 토큰을 구분하며 코드와 CSS는 역할 토큰만 사용한다. daphnis는 해시가 있는 완성본과 그림 전용 사본을 가져오고 같은 토큰을 다시 정의하지 않는다. 가져온 사본(`src/design-theme/`)과 생성 토큰은 손으로 고치지 않는다. 수치는 [라이트 사본](../../src/design-theme/tokens.light.json)과 [다크 사본](../../src/design-theme/tokens.dark.json)에서 확인하며 계산값 표를 문서에 복사하지 않는다.

아래 표는 역할과 검사 기준만 기록한다. 글자와 UI 그래픽의 대비는 실제 합성된 면에서 검사한다.

| 역할 | 뜻 | 검사 기준 |
|---|---|---|
| `state.active` | 활성 선·점·도형 테두리 | 3 이상 |
| `state.active-fill` | 선택한 면 | on-active 글자 4.5 이상 |
| `state.active-text` | 활성 글자 | 4.5 이상 |
| `ui.link` | 링크 | 4.5 이상 |
| `ui.focus` | 키보드 초점 | 3 이상 |
| `ui.progress` | 테마가 가진 UI 그래픽 색. 재생기에는 진행선이나 진행 고리가 없어 쓰는 곳이 없다 | 3 이상 |
| `figure.icon` | 도형 아이콘 | 글리프와 타일 3 이상 |
| `data.main` | 주 계열 | 핵심 파랑 면, 구분은 이름과 직접 라벨 |
| `data.compare` | 비교 계열 | 핵심 노랑 면, 구분은 이름과 직접 라벨 |
| `fg` | 본문과 그림 글자 | 4.5 이상 |
| `muted` | 보조 글자 | 4.5 이상 |
| `simple2.canvas-fill` | 설명용 그림 판 | 글자 대비 기준 적용 |
| `node` | 도형 면 | 글자 대비 기준 적용 |
| `page` | 문서 바탕 | 글자 대비 기준 적용 |
| `group-title` | 그룹 제목 | 4.5 이상 |
| `outline` | 도형 외곽선 | 3 이상 |
| `plate-border` | 판과 조작부 구분선 | 1.3 이상 |
| `card` | 카드 기본 면 | 글자 대비 기준 적용 |
| `card-on` | 밝힌 칸과 테이블 열 줄의 활성 면(내용이 찬 카드는 중립이라 쓰지 않는다) | 글자 대비 기준 적용 |

- 색 하나로 뜻을 전하지 않는다. 이름, 글자, 윤곽이 함께 간다. 글자 4.5 기준은 낮추지 않는다.
- 상태: 활성은 파랑, 주의는 노랑, 오류는 빨강, 정상은 초록이고 늘 아이콘과 글자가 함께 간다. 이 배정이 정본 값과 다르면 정본에서 고친다.
- `data.main`, `data.compare`는 선언 순서가 아니라 계열의 `role`이 정한다([차트](charts.md)). 같은 계열 이름은 모든 예제에서 같은 역할이다(`test/chart.test.js`).
- 사이트 기능 아이콘 면색과 앱 범용 색은 구분한다. 핵심 넷의 값은 앞의 값이고, 앱의 각 역할이 같은 색이라고 주장하지 않는다.
- 구성도 의미 아이콘은 작은 면 타일과 글리프이며 역할별 면과 윤곽을 갖는다. 이 역할 색은 공개 화면을 읽어 정한 해석이며 Things의 토큰이나 소스가 아니다.
- 표 열의 PK, FK 표시는 항상 있는 스키마 표시라 `color.muted`다. 칸 격자의 칸([칸 격자](grid.md))은 새 색 역할이 없고 `node`, `border`, `fg`, `surface`, `muted`, `card-on`, `state.active`의 기존 짝을 쓴다.
- 설명 판은 `simple2.canvas-fill`, 도형 면은 `color.node`, 조작 줄은 `color.page`를 쓴다. 중첩 그룹은 `group-1`부터 `group-3`까지 중립색 면의 밝기로 구분한다. 이름과 면으로 경계가 식별되는 도형에는 `simple2.surface-edge` 장식선을 쓰고, 의미를 전달하는 선에는 대비 3 이상의 역할색을 쓴다. 내부 표와 배지는 `simple2.separator` 한 규칙을 공유한다. 박스플롯의 중앙값·수염 같은 데이터 선은 `simple2.data-line`으로 구분한다.
- 색을 고른 도형은 재생 중에도 색 역할을 유지한다. 도형 외곽선은 1px, 색을 지정한 그룹은 1.5px로 유지하고 후광용 복제 윤곽을 그리지 않는다. 색을 지정하지 않은 도형의 활성 상태는 같은 굵기의 파란 외곽선이다. 선택 칸은 `simple2.row-selection` 면과 같은 모서리의 단일 선이다.
- 태그 글자는 `color.fg`이고 범주색은 글자 뒤의 옅은 바탕 띠로만 전한다. 태그 색은 갈래를 나누는 색이고 판정을 뜻하지 않는다.
- 범주 토큰은 design-tokens가 계열마다 원색(`color.category.<계열>.anchor`)에서 계산한다. `color.data.category-family.N`이 기록한 순서이고 `color.data.category.N`(면, 두 모드 같은 원색), `category-outline.N`(테두리), `category-on.N`(면 위 글자), `category-ink.N`(같은 계열 글자색, 못 맞추면 `fg`), `category-tint.N`(옅은 면), `category-label.N`(`required`이면 직접 라벨)이 번호로 따른다. 코드는 번호 토큰만 읽고 `src/chart-palette.js`의 `categoryPaint(index)`가 계열, 면, 테두리, 위 글자, 층(`tier`), 무늬, 간격, 모양, `needsLabel`을 한 번에 준다. 번호가 색 수를 넘으면 계열이 순환하고 층이 오르며 무늬(`category-pattern.N`)는 층 1부터, 모양(`category-shape.N`)은 층과 상관없이 범주 번호마다 고정된 순서로 바뀐다(번호를 모양 개수로 나눈 나머지). 색·무늬·모양 목록은 뒤에만 늘어나고, 늘면 순환 길이가 바뀌어 기존 범주의 칠이 달라지므로 칠은 판(`color.data.category-revision.N.{family,pattern,shape,step}`)으로 고정한다. 판 N은 세 목록의 앞쪽 개수와 무늬 간격 배율 step을 가진 숫자 토큰이고, `categoryPaint(index, { revision })`의 기본은 최신 판이 아니라 언제나 1판(일곱 계열, 무늬 3, 모양 4, step 0.5)이다. 덧붙인 색은 소스가 더 높은 판을 명시할 때만 쓰이고, 판을 고르는 소스 문법은 2판을 더하는 변경에서 함께 넣는다. 무늬 간격의 기준은 `size.chart.pattern-spacing`(8), 무늬 선 굵기는 `border.tag`이며 SVG 무늬 정의는 렌더러가 만든다.
- 상태 색(`state.*`)은 범주 번호와 무관하게 고정된 계열의 테두리를 가리킨다. 상태가 있거나 없다고 범주의 순서가 바뀌지 않는다.

#### 원본이 고르는 색 이름

원본이 직접 고르는 색 이름(흐름의 `tone`, 도형의 `fill=`, `stroke=`, `card=`)은 핵심 넷과 확장 순서를 따른 팔레트 계열 일곱(`blue`, `yellow`, `red`, `green`, `orange`, `purple`, `cyan`)과 무채색 `gray`다. 이름이 없는 점과 태그는 같은 순서로 색을 받는다(`src/tone.js`). 이전 체계의 이름과 별칭은 읽지 않는다. 차트 계열 수에는 상한이 없고 색 수를 넘는 계열은 위 색 계약의 무늬·모양·직접 라벨로 구분한다. 흐려진 행의 대비를 3으로 맞추라고 요구하지 않고, 면 위 대비가 낮은 표식은 색을 바꾸지 않고 라벨이나 모양으로 보완한다([차트](charts.md#그리기)).

### 색표와 글꼴

- 모든 그림의 SVG `width`는 같은 표준 캔버스 폭(`size.figure-canvas`, 960)이다. 그림 머리 `width wide`를 쓴 그림만 넓은 폭(`size.figure-canvas-wide`)이고, 문서에서는 본문 폭에 맞춰 줄어든다. 가운데 정렬은 SVG 파일이 아니라 문서 쪽 몫이다. GitHub README는 `<p align="center"><img src="docs/assets/그림.svg" alt="설명"></p>` 형식으로 넣어야 가운데에 선다(Markdown 이미지 문법으로는 정렬할 수 없다).
- 글꼴은 이 도구가 Pretendard, JetBrains Mono 파일(수학 기호용 Noto Sans, Noto Sans Math 포함)을 함께 배포하고 그림에 잘라 넣는다. 본문 글자 간격은 `tracking.text`(-0.3px)다([배치](layout.md)). 스킬의 글꼴 설치 줄은 지운다.
- HTML 페이지와 조작부는 `font.sans`의 시스템 글꼴, HTML 코드와 파일 이름은 `font.mono`를 쓴다. SVG 내부만 측정한 FigSans·FigMono 조각을 내장해 배치와 표시 폭을 일치시킨다. 글자 위계와 크기는 [배치의 글꼴 자리](layout.md#글꼴-자리)를 따른다. 페이지 큰 제목은 목록과 문서 모두 36px·700·줄 높이 1.2다.

### 조작과 선

장면 탭과 테마 선택은 최소 44px의 눌리는 영역을 갖는다. 선택·pressed·focus는 조작부의 simple2 역할 토큰을 쓴다. 좁은 화면에서는 탭이 줄바꿈하며 그림 캔버스는 가로로 탐색하고 페이지 전체에는 가로 스크롤을 만들지 않는다. HTML 재생기 탭 글자는 실제 선택 면 위에서 대비 4.5 이상이다. 재생기에는 재생, 일시정지, 배속, 반복 조작이 없고 조작은 장면 탭과 도구 막대([재생](playback.md#도구-막대와-전체-화면))뿐이다. 도구 막대는 Things에 대응 요소가 없는 확장이다. 모양과 크기는 폭 390·1440의 실제 화면에서 보았고 범위는 [표현 범위](expression-coverage.md#예제와-검증-범위)가 정한다. 실제 기기에서 눌러 본 검수는 하지 않았다(검증 요구사항, 미완료).

카드는 반지름 18px의 흰 표면과 두 겹 그림자(`simple2.shadow`)를 쓴다. 도형은 그림자 없는 평면이고 그림자는 떠 있는 조작에만 쓴다. 목록 폭은 960px, 카드 사이는 48px다.

선 역할은 둘뿐이다. 경계(도형 바깥 윤곽, 칩, 표 구분선, 원통 이음)는 1px, 관계(연결선과 카드 안 관계 그래프 선)는 `border.edge` 1.75px다. 지금 단계는 선 굵기를 바꾸지 않고 색이나 면만 바꾼다. 유일한 예외는 키보드 초점(`:focus-visible`)으로, 도형 자신의 윤곽을 `simple2.focus-width` 3px와 `--color-ui-focus`로 그린다. 모든 선은 그림과 함께 같은 비율로 커지고 줄어든다. 좁은 화면에서 줄어든 선은 폭 390 화면에서 보았고, 320과 430의 눈 검수는 하지 않았다(증거 표). 끝과 이음은 둥글다.

### 대비 기준

글자 기준과 UI 그래픽 기준은 라이트와 다크 모두에서 지킨다. 기준은 `test/contrast.test.js`와 관련 검사가 토큰 정본에서 풀어 잰다. 카테고리 면색(핵심 넷과 확장)은 값을 바꾸지 않으므로 면 자체에 일률 그래픽 대비를 요구하지 않고, 뜻은 이름·직접 라벨·무늬·모양이 함께 전한다.

| 쌍 | 기준 | 근거 |
|---|---|---|
| 본문 글자(`fg`), 보조 글자(`muted`)와 모든 면(`bg`, `node`, `surface`, `card-on`, `group-1`, `group-2`, `group-3`, `page`) | 4.5 이상 | WCAG 글자 기준 |
| 강조 글자(`state.active-text`: 링크, 카드 표시 ✓)와 그림 바탕, 노드, 카드 바탕, 문서 바탕 | 4.5 이상 | 같음 |
| 강조 UI 그래픽(`state.active`: 밝힌 선, 점, 테두리, 진행 고리, 초점 고리)과 그림 바탕, 그룹 바탕, 카드 바탕, 노드, 문서 바탕 | 3 이상 | WCAG 그래픽 기준 |
| `state.on-active` 글자와 `state.active-fill` 면 | 4.5 이상 | 같음 |
| 면 위 글자(`on`)와 카테고리 면 | 4.5 이상이면 글자를 놓고, 못 미치면 글리프만 놓고 글자는 면 밖에 둔다 | 검은색과 흰색 중 대비가 큰 쪽을 계산해 고른다 |
| 카드 태그 글자(`fg`)와 어느 톤 띠 | 4.5 이상 | 같음 |
| 밝히지 않은 행(`ink.dim`, `opacity.dim-ink`)의 `fg`, `muted` 글자와 `bg` | 4.5 이상 | 같음 |
| 도형 외곽선(`outline`)과 판, 그룹 셋, 도형, 카드 바탕 | 3 이상 | 외곽선 대비 3. `test/outline-contrast.test.js` |
| 그룹 제목(`group-title`)과 회색 그룹 셋 | 4.5 이상 | 같음 |
| 히트맵 칸 숫자와 그 칸 색 | 4.5 이상 | 칸마다 어두운 글자와 밝은 글자 중 대비가 큰 쪽을 빌드 때 고른다 |
| 경계(`border`)와 그림 바탕, 노드, 그룹, 카드 바탕, 문서 바탕 | 3 이상 | WCAG 그래픽 기준 |
| 켜진 탭 표시(`border` 색 고리)와 탭 묶음 바탕 | 3 이상 | UI 상태 표시도 그래픽 기준이다. 알약 면(`ui.control-on`)은 글자 대비 4.5만 맡는다 |
| 차이 차트의 0선, 행 기준 점선, 잘린 축의 지그재그(`muted`)와 그림 바탕 | 4.5 이상 | 값 차이를 전하는 그래픽이라 `muted`의 글자 기준을 쓴다 |
| 꾸밈 요소: 격자와 축, 히트맵 값 0 칸, 신뢰구간 띠와 덤벨 범위 막대기 | 1.5 이상 | WCAG 적용 대상 밖이다. 값은 숫자로도 적히고 이 요소는 구조만 돕는다 |
| 꾸밈 요소: 판 테두리(`plate-border`)와 문서 바탕(`page`) | 1.3 이상 | WCAG 적용 대상 밖이다. 판 모양만 잡고 판 안 도형은 각자 3을 맞춘다 |

### 변환과 검사

| 스킬 규칙 | 이 도구 |
|---|---|
| 변환은 `render_figures`로만 | `render_figures`가 `.dap` 원본마다 `daphnis render --strict`를 부른다. 경고도 실패다 |
| 실험 차트 값 손 기재 금지, 비율에 신뢰구간 | `docs/experiments/` 아래 차트에 `--require-data --require-ci`를 붙인다([차트](charts.md)) |
| 원본과 만든 그림 함께 커밋 | 그대로 |
| 변환 뒤 그림을 열어 겹침, 잘림, 빈 영역 확인 | [그림 검사](figure-check.md)는 겹침과 잘림의 자동 증거를 낸다. 눈 확인을 대신하지 않으며 빈 영역은 검사 항목이 없다 |
| 다시 변환 뒤 `git diff` 없음 | [배치](layout.md)의 결정성 요구사항이 지킨다 |
| 원본에 색, `config`, `sketch` 없음 | 색 줄과 hex는 문법에 없다. 도형 색은 팔레트 이름 `fill=`, `stroke=`, `card=`만 받아 검사 항목에서 지운다 |

- 결과는 움직이는 SVG `{이름}.svg` 하나다. 무엇이 언제 움직이는지는 [재생](playback.md)을 따른다. HTML 재생기는 문서 저장소에 넣지 않는다. 문서 저장소에 스크립트가 든 파일을 늘리지 않기 위해서다.
- `npm run check`는 토큰 생성물 최신 여부, 재정의, 하드코딩을 실패로 지키는 정확성 관문이다. 파일 300줄, 함수 40줄, 매개변수 3개, 비용 주석 누락은 `npm run check:advisory`가 알리기만 한다. 두 검사는 줄 단위 정규식이라 여러 줄 매개변수 목록이나 블록 주석 안의 중괄호를 바르게 읽지 못하고, 수치를 맞추려고 일관된 코드를 쪼개거나 근거 없는 점근 표기를 적게 만들기 때문이다. 실행 오류(없는 경로, 잘못된 옵션)는 이 명령도 종료 코드 2로 실패한다. 형태는 `test/rule-contract.test.js`가 지킨다.

### 바꾸는 순서

1. 이 도구가 스킬의 다섯 그림(맥락, 구성 요소, 순서, 상태, 데이터)과 스킬이 쓰는 차트 종류를 구현하고, 모든 예제가 그림 검사를 통과한다.
2. repo-docs-figures 스킬의 도구 표, 색표, D2 절, Vega-Lite 절을 이 도구 기준으로 다시 쓰고, `render_figures`에 `.dap` 변환을 넣는다.
3. 스킬 저장소의 형식 검사가 `total 0`이 된 뒤 skill-sync로 설치한다.
4. 문서 저장소마다 `docs/assets/*.d2`와 `*.vl.json`을 `.dap`로 옮기고 다시 변환한다. 옮긴 뒤 D2와 Vega-Lite 변환 분기를 지운다.

- 1번이 끝나기 전에 스킬을 바꾸지 않는다. 없는 도구를 쓰라고 적는 스킬은 스킬의 정직한 상태 규칙을 어기기 때문이다.
- 이 도구의 다음 판은 `daphnis` 2다. 원본의 첫 비주석 의미 줄은 `daphnis 2`여야 하고, 판 1이거나 판 줄이 없으면 줄 위치와 함께 오류다. 읽는 어댑터와 옛 이름 전용 경로는 없고 읽는 확장자는 `.dap`뿐이다. 스킬의 변환 명령은 `daphnis`만 부른다.

### 요구사항

| 요구사항 | 검증 계획 |
|---|---|
| 스킬의 다섯 그림 템플릿을 새 문법으로 옮긴 원본이 검사를 통과한다. | 템플릿마다 원본을 만들어 `check` 실행 |
| 스킬의 차트를 `data` 줄로 그린다. | 예시 `summary.json`으로 차트별 원본 변환 |
| 같은 원본을 다시 변환해도 git 차이가 없다. | 두 번 변환 뒤 `git diff` 확인 |
| 확장 색 후보를 실제 크기 라이트·다크 구성 요소로 비교해 고른다. | 후보 비교 화면 검수. 팔레트 개정 1의 채택 기록은 소유 저장소 `themes/simple2/tokens.json`의 `review`에 있고, 제품 화면에서 확인한 범위는 [표현 범위](expression-coverage.md#예제와-검증-범위)가 정한다. 색각 이상 실제 사용자 시험은 검증 요구사항, 미완료 |
| 공식 Things 기준과 화면 비교를 마친다. | 수용 게이트(모바일 320·390·430px, 데스크톱 실제 크기, 라이트·다크, 정지·재생). 확인한 범위는 [표현 범위](expression-coverage.md#예제와-검증-범위)가 정하고 그 밖은 검증 요구사항, 미완료. 공식 이미지와의 비교는 역할 비교이며 현재 네이티브 앱 전체와의 픽셀 대조가 아니다 |

## 단점

- 문서 저장소의 기존 D2, Vega-Lite 원본을 모두 다시 써야 한다.
- 스킬이 이 도구의 배포 방법(npm 패키지나 저장소 경로)에 묶인다.
